# Руководство пользователя NectarinePanel

[English](../en/user-guide.md) · [Українська](../uk/user-guide.md) · **Русский** ·
[Polski](../pl/user-guide.md)

Это руководство предназначено для тех, кто развёртывает проекты и управляет
ими через веб-интерфейс. Установка сервера и изменение исходного кода описаны в
[руководстве разработчика](developer-guide.md).

> NectarinePanel управляет привилегированными операциями на одном VPS. Храните
> резервную копию вне сервера, проверяйте восстановление и выдавайте каждому
> пользователю только необходимый доступ.

## Установка

Устанавливайте панель на отдельный VPS с Ubuntu 24.04 LTS, доменом с A/AAAA
записью на VPS, минимум 2 GB RAM, 20 GB свободного места и доступом root или
sudo. Клонируйте проверенный тег релиза и запустите установщик от root:

```bash
git clone --branch vX.Y.Z --depth 1 https://github.com/JanekDeveloper/NectarinePanel.git
cd NectarinePanel
sudo ./installer/install.sh --domain panel.example.com --email admin@example.com
```

| Параметр | Назначение |
| --- | --- |
| `--domain`, `--email` | Публичный домен панели и email для Let's Encrypt. |
| `--admin-user`, `--admin-password` | Логин и пароль первого владельца. Пароль лучше вводить интерактивно или брать из защищённого хранилища. |
| `--storage-root` | Путь к постоянному хранилищу панели и проектов. |
| `--telegram-token`, `--telegram-owner-id` | Необязательные токен Telegram-бота и ID чата владельца. |
| `--public-ip` | Публичный IP VPS, если автоопределение не подходит. |
| `--source` | Доверенная локальная копия исходного кода вместо клонирования. |
| `--repository`, `--ref` | URL репозитория и закреплённый Git-тег/ref для установки. |
| `--max-upload-mb` | Максимальный размер загружаемых файлов в MB. |
| `--backend-port`, `--frontend-port`, `--agent-port`, `--adminer-port` | Переопределение занятых loopback-портов. |
| `--non-interactive` | Не задавать вопросы, а завершаться при отсутствии обязательных значений. |
| `--skip-ssl` | Не выпускать сертификат; используйте только при внешнем завершении TLS. |
| `--dry-run` | Проверить план установки без изменения VPS. |

Установщик настроит службы, Nginx, TLS, PostgreSQL, Valkey и System Agent. Если
не передан `--admin-password`, начальный пароль владельца будет показан один раз;
сразу сохраните его в менеджере паролей. Откройте `https://panel.example.com`,
войдите, смените временные данные и проверьте
`systemctl status vps-panel-backend vps-panel-worker vps-panel-frontend`.

Используйте только закреплённый тег релиза, а не непроверенную движущуюся ветку.
Порядок обновления описан в [Обновление панели](#обновление-панели), параметры
установщика — в [документации по установке](installation.md).

## 1. Вход и выбор языка

Откройте адрес панели и войдите под учётной записью, созданной установщиком или
владельцем. Язык меняется на странице входа или в боковом меню. Доступны
русский, английский, украинский и польский. Выбор сохраняется в браузере и
файле cookie.

Если настроен вход через Telegram, начните вход в панели, откройте бота по
показанной ссылке и подтвердите короткоживущий запрос. Вернитесь в ту же вкладку
браузера — сессия завершится автоматически. Не подтверждайте запрос, который
вы не создавали.

## 2. Роли и доступ

| Роль | Доступ |
| --- | --- |
| `owner` | Полный доступ, пользователи, безопасность и все проекты. |
| `admin` | Все проекты и операционные действия, кроме управления владельцем и безопасностью. |
| `maintainer` | Только назначенные проекты: развёртывание, среда выполнения, файлы и редактирование переменных. Без просмотра секретов и удаления проекта. |
| `viewer` | Чтение назначенных проектов, логов, файлов и замаскированных переменных. |

Членство в проектах применяется к ролям `maintainer` и `viewer`. Скрытая кнопка
не является защитой: серверная часть проверяет каждую операцию.

## 3. Создание проекта

Откройте **Проекты → Новый проект**. Проще начать с шаблона; пользовательский
проект позволяет настроить все параметры среды выполнения.

### Выбор источника

- **Git-репозиторий**: укажите HTTPS-адрес и ветку. Каждое развёртывание
  клонирует новый неизменяемый релиз. Можно развернуть конкретную ветку, тег
  или коммит.
- **Файлы / ZIP**: создайте проект без репозитория, затем загрузите `.zip` во
  вкладке **Деплои**. Архивы с небезопасными путями, ссылками или чрезмерным
  размером после распаковки отклоняются.

Для приватного репозитория GitHub настройте в параметрах проекта один из
вариантов:

1. **Fine-grained token**: создайте на GitHub токен с ограниченным доступом
   только к нужному репозиторию и разрешением **Contents: Read-only**. Сохраните
   его в NectarinePanel как учётные данные типа «токен». Используйте обычный
   HTTPS-адрес и не вставляйте токен в него.
2. **Deploy key**: создайте отдельную пару ключей SSH, добавьте открытый ключ в
   разделе GitHub **Repository → Settings → Deploy keys** без права записи, а
   закрытый ключ сохраните в NectarinePanel как ключ развёртывания. Используйте
   SSH-адрес репозитория.

Учётные данные хранятся в зашифрованном виде и не попадают в параметры задач
развёртывания. При изменении доступа к репозиторию сразу удалите или замените
ключ.

### Выбор среды выполнения

| Среда выполнения | Для чего | Важное поведение |
| --- | --- | --- |
| Контейнер Docker | Большинство API, ботов и веб-приложений | Собирает `Dockerfile` репозитория; обеспечивает изоляцию и применение ограничений ресурсов. |
| Docker Compose | Приложения из нескольких контейнеров | Запускает файл Compose; политика ресурсов используется только для мониторинга. |
| Статический Nginx | Собранные статические сайты | Публикует указанный выходной каталог без процесса приложения. |
| systemd | Приложения, запускаемые непосредственно на сервере | Запускает команду старта от отдельного непривилегированного пользователя. |
| PM2 | Приложения Node.js под управлением PM2 | PM2 работает внутри ограниченного системного модуля проекта. |
| Minecraft Forge | Forge-сервер | Отдельные настройки, консоль, файлы и резервное копирование. |

Изменение команды запуска в панели не переписывает `Dockerfile` из репозитория.
Для Docker команду контейнера определяют `CMD` и `ENTRYPOINT` в Dockerfile.
Измените их или используйте настраиваемый сценарий запуска. Команда запуска из
панели применяется к средам, работающим непосредственно на сервере, и при
первоначальной генерации шаблона.

### Проверка перед первым деплоем

- ветка существует, а учётные данные дают доступ на чтение;
- команды сборки и запуска соответствуют выбранной среде;
- внутри Docker приложение слушает `0.0.0.0`, а не только `127.0.0.1`;
- порт проксирования совпадает с портом приложения;
- секреты находятся в **Переменных**, а не в Git;
- постоянные данные смонтированы из `shared/`;
- HTTP-проверка работоспособности возвращает код 2xx или 3xx.

## 4. Развёртывание и откат

Откройте проект и вкладку **Деплои**.

- Развёртывание из Git может принимать конкретную ревизию. Пустое значение
  использует настроенную ветку.
- Развёртывание из ZIP принимает только `.zip` и предназначено для проектов без
  репозитория.
- Активная задача показывает состояние и ход выполнения.
- История релизов содержит ревизию, время, путь, результат и сохранённый лог.

Успешный деплой создаёт релиз в
`projects/{project_id}/releases/{release_id}` и атомарно направляет `current` на
него. Неуспешный релиз не заменяет активный.

Для отката выберите успешный релиз, подтвердите его имя или ревизию и запустите
операцию. Откат активирует релиз, но не восстанавливает базы данных и постоянные
файлы из `shared/`. При необходимости восстановите их из соответствующей
резервной копии.

Если задача завершилась ошибкой, откройте лог и исправьте первую значимую
причину. Повторный деплой без изменения исходников или конфигурации обычно
завершится так же.

## 5. Управление запущенным проектом

В обзоре отображаются состояние и доступные метрики. Кнопки соответствуют
фактическому состоянию: **Запустить** видна для остановленного проекта,
**Остановить** и **Перезапустить** — для запущенного.

- **Логи** показывают журналы среды выполнения и по возможности обновляются в
  реальном времени.
- **Консоль** отправляет команды в среду выполнения проекта и не является
  оболочкой с правами суперпользователя.
  Docker-команды выполняются в контейнере проекта, Minecraft использует RCON,
  а systemd, PM2 и Compose предоставляют ограниченные операции.
- **Cron** выполняет команды через ту же защищённую границу среды выполнения.
  Статические проекты не поддерживают задания cron.

Сообщение `no job control in this shell` означает, что интерактивная оболочка
запущен без настоящего TTY. Обычные команды работают, но `Ctrl+Z`, `fg` и `bg`
недоступны. В веб-консоли используйте неинтерактивные команды.

## 6. Переменные и секреты

Вкладка **Переменные** — источник переменных окружения для среды выполнения.

- Пароли, токены и другие учётные данные отмечайте как секретные.
- Секретные значения шифруются и маскируются в списке.
- **Показать** требует ввода точного ключа. Действие попадает в аудит без
  открытого значения.
- **История** хранит версии. Откат создаёт новую версию и не стирает историю.
- Импорт `.env` читает буквальные записи `KEY=value` и не подставляет переменные
  оболочки. Режим **Объединить** обновляет переданные ключи, а **Заменить**
  удаляет ключи, которых нет в импортируемом файле.

Изменение переменных не запускает деплой автоматически. Перезапустите или
повторно разверните проект. Показанный секрет считайте раскрытым: не вставляйте
его в логи, снимки экрана, систему задач или чат.

## 7. Безопасная работа с файлами

Корень проекта содержит:

```text
releases/   неизменяемые релизы
current     символическая ссылка на активный релиз
shared/     постоянные файлы между деплоями
```

Для перехода нажмите папку или сегмент пути. Поддерживаемые массовые операции
работают с несколькими выбранными элементами. Подсчёт размера большой папки
может занять время.

`current` — символическая ссылка, а не обычная папка. Панель безопасно
разрешает ссылки внутри корня проекта. Если приложение пишет данные внутрь
контейнера без привязки каталога из `shared/`, этих файлов не будет в проводнике
и они могут исчезнуть при замене контейнера. SQLite, загруженные файлы и прочее состояние
храните, например, в смонтированной папке `shared/data`.

Перед удалением или перемещением остановите приложение, которое может писать в
эти файлы. Перед массовыми необратимыми изменениями создавайте резервную копию.

## 8. Домены и TLS

До добавления домена создайте DNS A/AAAA запись на адрес VPS и дождитесь её
публичного разрешения. Во вкладке **Домены**:

1. добавьте имя хоста и проверьте порт проксирования;
2. проверьте созданный HTTP-маршрут;
3. выпустите сертификат Let's Encrypt;
4. проверьте HTTPS и проверку работоспособности приложения.

Не запускайте принудительный выпуск многократно при ошибках DNS или
маршрутизации: Let's Encrypt ограничивает частоту запросов. Обновление
выполняется по расписанию, а срок действия и отпечаток сертификата сохраняются
панелью.

## 9. Базы данных

Сервер базы данных и база проекта — разные сущности. Сначала добавьте учётные
данные сервера, затем создайте или подключите базу. Поддерживаются PostgreSQL,
MySQL/MariaDB, SQLite и Redis/Valkey с возможностями конкретной СУБД.

- Строку подключения можно добавить в переменную проекта.
- Создание дампа, восстановление и удаление выполняются как фоновые задачи.
- Для восстановления требуется совместимый дамп и подтверждение.
- Перед восстановлением или удалением SQLite остановите проект.
- Redis/Valkey показывает подключение и состояние, но не имитирует реляционные
  таблицы или несуществующую изоляцию.

Перед необратимой миграцией создавайте свежий дамп и проверяйте приложение после
восстановления.

## 10. Резервное копирование и восстановление

Автоматическое резервное копирование выключено, пока не настроена политика. В
копию проекта можно включить окружение, активный релиз, общие данные,
загруженные файлы, логи, дампы баз данных и данные Minecraft. Полная копия
панели может содержать базу панели, конфигурацию, узлы Nginx, проекты и состояние
планировщика.

У каждого архива есть манифест и контрольная сумма SHA-256. Статус «успешно»
доказывает создание архива, но не возможность восстановления. Для рабочей
среды:

1. настройте расписание и срок хранения;
2. копируйте критичные архивы за пределы VPS;
3. проверяйте восстановление на временном проекте или сервере;
4. фиксируйте дату последней успешной проверки.

Восстановление проверяет тип архива, совместимость, контрольную сумму и целевой
проект. Оно может заменить файлы, поэтому сначала остановите проект и создайте
новую резервную копию.

## 11. Мониторинг и ограничения ресурсов

Главная страница мониторинга показывает загрузку процессора, памяти, диска и
сети VPS, а также предупреждения. Страница проекта показывает показатели среды
выполнения и диска только при наличии измерения.
«Нет данных» означает отсутствие валидного измерения, а не нулевую нагрузку.

Владелец и администратор могут включить ограничения:

- ограничения процессора и памяти применяются для поддерживаемых сред Docker и
  сред, запускаемых непосредственно на сервере;
- лимиты Docker Compose только отслеживаются;
- ограничение диска создаёт предупреждение, но не квоту файловой системы;
- для Minecraft необходимо минимум 512 MB сверх настроенного JVM `Xmx`.

Проверка работоспособности должна быть быстрой, не требовать авторизации и
подтверждать готовность сервиса. Ошибка или ответ вне диапазонов 2xx/3xx создаёт
одно предупреждение без дубликатов.

## 12. Пользователи, аудит и Telegram

Владелец управляет учётными записями в **Настройки → Пользователи**.
Администратор имеет глобальный операционный доступ. Пользователей с ролями
`maintainer` и `viewer` необходимо назначить на проекты в настройках проекта.
Последнего активного владельца отключить нельзя.

Проверяйте **Аудит** после изменения прав, просмотра секретов, восстановления,
изменения доменов и необратимых операций. Сведения аудита не содержат пароли и
секретные значения.

Telegram необязателен. Владелец задаёт токен бота и разрешённый идентификатор
пользователя Telegram в настройках, затем перезапускает сервис бота при их
изменении. Бот доставляет предупреждения и выполняет подтверждённые операции. Не используйте
историю чата как хранилище секретов.

## Обновление панели

Обновляйте панель до закреплённого проверенного релиза в окно обслуживания. До
начала создайте и проверьте резервную копию панели и важных проектов вне VPS.

1. Подключитесь к VPS и выберите тег релиза, а не непроверяемую движущуюся ветку.
2. Выполните `sudo /opt/nectarine-panel/installer/update.sh --ref vX.Y.Z`.
3. Дождитесь резервного копирования панели, миграций, сборки web-клиента,
   перезапуска служб и проверки доступности.
4. Войдите снова, проверьте проекты, мониторинг, развёртывания и постоянные
   данные. При ошибке проверки смотрите `systemctl status vps-panel-backend vps-panel-worker`.

Для предварительной проверки используйте `--dry-run`. `--source` применяйте
только для доверенной локальной копии. Не прерывайте обновление и не заменяйте
файлы вручную во время его работы; при необходимости восстанавливайтесь из
проверенной резервной копии.

## 13. Контрольный список для рабочей среды

Ежедневно или после предупреждения:

- проверьте проекты с ошибками, проверки работоспособности, диск и непрочитанные
  уведомления;
- изучите лог до многократных перезапусков;
- убедитесь, что резервные копии по расписанию продолжают создаваться.

После релиза или изменения конфигурации:

- проверьте состояние и логи;
- проверьте публичный HTTPS-адрес;
- убедитесь, что постоянные данные пережили деплой;
- быстро выполните откат, если релиз неработоспособен.

Регулярно:

- обновляйте NectarinePanel только с релиза, отмеченного тегом;
- меняйте учётные данные пользователей, Git, баз данных, Telegram и приложений;
- удаляйте неиспользуемые учётные записи, назначения на проекты, домены и копии;
- проводите и документируйте проверку восстановления вне основного VPS.

## 14. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Git не клонирует репозиторий | URL, ветку, доступ токена или ключа развёртывания на чтение и срок действия учётных данных. |
| Развёртывание успешно, но сервис недоступен | Лог среды выполнения, адрес прослушивания, порт проксирования, окружение и путь проверки работоспособности. |
| Файл исчез после повторного развёртывания | Он записан в неизменяемый релиз или слой контейнера, а не в `shared/`. |
| `current` не открывается | Нет успешного релиза или цель ссылки удалена; проверьте историю. |
| Метрик нет | Проект ещё не запускался, сборщик или агент недоступен либо среда не отдаёт метрику. |
| Не выпускается TLS | Публичный DNS, порты 80/443, маршрут Nginx и ограничения частоты запросов. |
| Ответ 403 | Роль или назначение на проект не разрешает операцию. |
| Ответ 502 | Серверная часть не завершила проверенную операцию агента; владелец должен проверить логи панели и агента. |

Диагностика сервера, установка, обновление и восстановление описаны в
[руководстве разработчика](developer-guide.md). Технические справочные
материалы остаются в каталоге [`docs/`](./).
